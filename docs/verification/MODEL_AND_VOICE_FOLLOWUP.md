# Model capability and voice follow-up

This follows the streaming/media repair in commit `69875c1`. All earlier output persistence, real Save As, image Save/Share, model-first selection, and millisecond timing changes are retained.

## Reference and implementation

Reviewed PocketPal AI at commit [`6848b02d70370f2dd512da104284de1582aa6570`](https://github.com/a-ghorbani/pocketpal-ai/tree/6848b02d70370f2dd512da104284de1582aa6570), specifically `src/utils/thinkingCapabilityDetection.ts`, `src/api/completionEngines.ts`, `src/utils/modelCaps.ts`, `src/store/ModelStore.ts`, and `src/components/ChatInput/ChatInput.tsx` and its thinking tests. PocketPal is MIT licensed, copyright 2024 Asghar Ghorbani. This change independently implements the template-probing principle in NeuroMesh's existing Dart/Kotlin/C++ architecture; it does not copy PocketPal source or introduce its React Native dependencies.

A runtime function named `common_chat_templates_support_enable_thinking` actually returns reasoning parser support, which by itself does not prove a template can disable reasoning. NeuroMesh now probes enabled and disabled formatted prompts, with actual reasoning parser metadata, to distinguish toggleable, always-on, absent and unknown capabilities. The classification takes no model name or author. Supported toggles pass `enable_thinking` into the embedded template; unsupported templates keep their natural behavior. Always-on models show active Think with a truthful explanation. Other unsupported/unknown modes explain the limitation. Existing load failure cleanup and generation-identity guards remain intact.

The initial native schema budget could omit TTS even when synthesis was available. Native schema annotations are now compacted while retaining validation constraints, property names and literal values; a small context regression asserts both image and audio tools are offered. Full registry validation remains unchanged. The LLM still decides every optional action; no request keywords select tools.

Hugging Face browsing now filters by author/organization, validates handles before networking and verifies response owners. Setup explains model versus app permissions, links the existing Tools & permissions screen, and that screen reads actual Android microphone/camera grants with lifecycle refresh. Reading status never requests access. Models grant no Android permissions themselves.

`SpeechVoiceCatalog` offers only installed local speakers, valid saved clones with their engine installed, and detected offline Android voices. `list_voices` pages the catalog and returns opaque IDs and labels; it exposes no reference recordings or paths. TTS accepts an exact `voice_id`, checks language/availability, prevents conflicting overrides and routes selected clones locally. Reference selection is scoped and restored after synthesis. Existing remote speech placement remains available for the default path. Explicit clone selection never silently substitutes another voice on failure.

The call header is a visible voice selector; saved clones are no longer hidden by a non-English language setting. Choosing an English clone switches the language while preserving the selected voice, disables the previous system-voice override and bypasses worker placement for that explicit voice. Missing engines are shown as unavailable. Invalid/missing saved references report errors; unsafe filenames and symlinks are rejected.
